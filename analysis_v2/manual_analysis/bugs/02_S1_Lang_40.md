## The bug and the fix
**Fix in one line:** `contains(str.toUpperCase(), searchStr.toUpperCase())` replaced by an explicit loop over `str.regionMatches(true, i, searchStr, 0, len)` (locale-independent case-insensitive search).

**Failing test(s) (shown to the model in both modes):**
- `org.apache.commons.lang.StringUtilsEqualsIndexOfTest::testContainsIgnoreCase_LocaleIndependence` — `junit.framework.AssertionFailedError: en: 0 ß SS`

**Developer fix diff (shown to the model ONLY in postfix):**
